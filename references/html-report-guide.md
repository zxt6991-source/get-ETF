# HTML 富交互报告规范（借鉴 `examples/消费ETF挑选报告-20260919.html`）

当用户要的不只是"结论"，而是一份**可阅读、可分享、带图表的报告**时，用 HTML 形态交付。
本文件把示例报告（消费 ETF，44 只候选 → 7 只代表品种 → 7 个跟踪指数）的页面结构、设计 token、图表规格拆解成可复用规范。**示例文件本身就是最好的模板：复制它、替换数据即可。**

## 一、什么时候用 HTML

| 交付形态 | 适用 | 实现方式 |
| --- | --- | --- |
| 对话内精简表 | 用户只想要结论/排名 | 直接输出 Markdown 表格 |
| **HTML 富交互报告** | 要图表、要分享、要存档、汇报用 | 本规范；对话内用 `create_document`，落盘用 `write_file` + `show_artifact` |
| 飞书文档 / 表格 / Base | 要协作、要后续更新 | `lark-doc` / `lark-sheets` / `lark-base` |

**外部依赖取舍（重要）**：示例报告用 CDN 引入 ECharts（`https://cdn.jsdelivr.net/npm/echarts@5/...`），图表精美但**离线不可用**。
- 用 `create_document` 产出对话内 HTML 时，必须去掉外部脚本（该工具要求自包含）：把图改成**内联 SVG**、纯 CSS 条形图，或退化为带色块的表格。
- 落盘成工作区文件并要求任何环境都能打开时，需把 `echarts.min.js` 内联或本地化，否则在断网/受限环境里图表区会是空白。
- 只做内部口头汇报、确定有网，保留 CDN 最省事。

## 二、页面结构（照抄这个骨架）

```
h1  「赛道」ETF 挑选报告
.sub 数据截止 <日期>｜分析范围：<筛选口径>｜候选 N 只 → 代表品种 M 只，覆盖 K 个跟踪指数

[KPI 4 卡]  候选总数 / 入选打分数 / 赛道估值水位 / 赛道近1年表现

一、结论先行：按偏好选择      ← 4 张 .rec 卡片（决策矩阵，非唯一答案）
二、综合评分与排名            ← 表1 + 横向条形图
三、候选池（第 1 步）          ← 表2（含是否入选及原因）
四、编制规则解构（第 2 步）     ← 表3
五、行业穿透与集中度（第 3 步）  ← 表4 + 集中度对比图
六、历史表现（第 4 步）         ← 表5 + 收益柱状图 + 风险收益散点图
七、价值与估值（第 5 步）       ← 表6 + 估值/股息双轴图
八、风险与预警                ← 编号条目，点名到具体标的与字段缺口
九、数据来源                  ← 表7（数据项/来源/截止日）
.disc 免责声明  .foot 报告生成时间 + 分析方法链条
```

### 各表列定义（与示例一致）

| 表 | 列 |
| --- | --- |
| 表1 排名 | 排名 / ETF / 跟踪指数 / 综合分 / 可交易性 / 编制质量 / 集中度 / 历史表现 / 价值 / 画像标签 |
| 表2 候选池 | 代码 / 名称 / 跟踪指数 / 规模(亿元) / 近20日均成交(亿元) / 管理+托管 / 上市日 / 是否代表品种 |
| 表3 编制 | 跟踪指数 / 选样规则 / 加权·复制 / 调仓 / 成分股数 / 单股权重上限 |
| 表4 集中度 | 跟踪指数 / 第一大行业（申万一级）/ 权重 / 第二大行业 / 权重 / 前十大权重 / 第一大个股 / 结构定性 |
| 表5 表现 | ETF·跟踪指数 / 近1年收益 / 近3年年化 / 近5年年化 / 最大回撤(3年) / 最大回撤(5年) / 年化波动率(3年) / 信息比率(3年) |
| 表6 估值 | 跟踪指数 / PE(TTM) / PE历史分位 / PB / PB历史分位 / 股息率 / 未来两年盈利增速 / 估值判断 |
| 表7 来源 | 数据项 / 来源 / 截止日 |

> 表1 的五个维度列名与 `scripts/etf_screen.py --format json` 输出的 `dims` 一一对应（liquidity/design/concentration/performance/valuation），可直接把脚本结果灌进页面。

## 三、设计 token（复制示例 `:root` 即可保持风格统一）

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--ink` / `--ink2` / `--ink3` | `#1a1d21` / `#4a5158` / `#7b848d` | 主/次/辅助文字 |
| `--line` / `--bg` / `--card` | `#e6e9ee` / `#f7f8fa` / `#ffffff` | 分隔线 / 页背景 / 卡片 |
| `--up` / `--down` | `#d9432f` / `#1a9c6b` | **红涨绿跌**（A 股习惯），涨用红、跌用绿 |
| `--accent` / `--accent-soft` | `#1f5fa8` / `#eaf1fa` | 主色（标题左边框、主数据条） |
| `--warn` / `--warn-bg` | `#b7791f` / `#fdf6e7` | 预警框、预警标签 |

关键类名（示例中已定义，直接复用）：
`.wrap`(max-width 1120px) · `.card` · `.grid.g4/.g3` · `.kpi`(`.lab`/`.val`/`.note`) · `.tblwrap`(横向滚动) · `.num`(右对齐 + `tabular-nums`) · `.chart`(360px) / `.chart.sm`(320px) · `.pill.p-blue/.p-green/.p-warn/.p-gray` · `.note-box` · `.rec` / `.rec-top` · `.src` · `.disc` · `.foot`
配色约定：主数据条 `#1f5fa8`，对比数据条 `#c98b3a`，浅色辅助 `#9dbcd9`，基准/无关项 `#8b939b`。

## 四、图表规格（示例用了 5 张）

| id | 位置 | 类型 | 说明 |
| --- | --- | --- | --- |
| `chartScore` | 二 | 横向条形 | x 轴为综合分（**最小值截断，如 min 45**，否则分差看不清），y 轴标的名 `inverse:true`，条末直接标数值 |
| `chartConc` | 五 | 分组柱状 | 「前十大权重占比」+「第一大行业权重」双系列，y 轴 max 100 带 `%`；缺数据的指数填 `null`（图上留缺口，不要填 0） |
| `chartPerf` | 六 | 分组柱状 | 「近1年收益」+「近3年年化」，**逐条按正负染色**（红正/绿负），x 轴标签 `rotate:26` 防重叠 |
| `chartRisk` | 六 | 散点 | x=近3年年化收益，y=最大回撤（**收益越大越右、回撤越大越上**，右下角即"高收益低回撤"），带 `name` 标签，并把基准（如沪深300）用灰色单独放入对比 |
| `chartValue` | 七 | 柱 + 折线双轴 | 左轴 PE/PB 历史分位（柱），右轴股息率（折线，max 设为 8 左右） |

图表硬性要求：① 每张图必须有标题性上下文文字；② 数值单位统一（百分比一律 `%`）；③ tooltip 对 `null` 显示 `—` 而不是 `null%`；④ 图与表并列，表给精确值、图给对比直觉。

## 五、决策矩阵卡片写法（结论先行的核心）

每张 `.rec` 卡片一个「偏好 → 标的」：

```
① 要<偏好关键词> → <ETF 简称>（<代码>）
   跟踪 <指数名称>（<指数代码>）｜规模 <x> 亿｜费率 <y>%
   <一句话理由：用具体数字支撑，如"前十大权重仅 53.0%，全场最低">
   <代价/风险：如"波动率最高、近 1 年跌幅最深">
   综合分 <s>，排名第 <n>。
```

要点：
- 卡片数量 **3～5 张**，覆盖"分散 / 低估值高股息 / 高弹性 / 底仓流动性"等典型偏好，不要给唯一答案。
- **必须写"代价"**：把该标的的短板（波动、回撤、规模、溢价、汇率）直接写在推荐里，不藏在后面章节。
- 偏好在卡片标题里用「要 X → 标的」句式，读者扫标题就能定位自己。
- 若某标的数据不全，要像示例那样直接说明"综合分排名第 1 的含金量因此打折"。

## 六、风险与预警节的写法

示例不是泛泛而谈，而是**逐条点名到标的与字段**，按这个套路写 5～7 条：
1. **赛道系统性风险**（如"近 3 年全赛道跑输基准、信息比率为负、低估值不构成上涨理由"）；
2. **集中度预警**（点名具体标的 + 权重数字）；
3. **规模与流动性预警**（点名规模/成交额偏低的标的）；
4. **跨境品种额外风险**（QDII 额度、场内溢价、汇率）；
5. **估值分位失真**（成分股调整导致历史序列不可比，举例说明调整事件）；
6. **数据缺口**（哪些字段全部缺失、对打分的影响、按剩余权重重归一化的事实与建议）。

## 七、数据纪律（HTML 版同样适用）

- 页头 `.sub` 必须写：数据截止日、分析范围（筛选口径）、候选数 → 入选数 → 覆盖指数数。
- 表7 逐项列「数据项 / 来源 / 截止日」；页脚 `.foot` 写报告生成时间 + 分析方法链条。
- 缺失字段显式写「待补」，并在风险节说明它对分数的影响，**不要用 0 或空白蒙过去**。
- 结尾 `.disc` 固定免责声明：基于公开数据和量化分析，仅供参考，不构成投资建议；市场有风险，投资需谨慎；过往表现不预示未来收益。

## 八、从数据到页面的操作顺序

1. 抓数（见 `data-sources.md`）→ 填成候选池 CSV（字段见 `scoring-card.md`）；
2. `python3 scripts/etf_screen.py candidates.csv --format json --out result.json` 得到五维分与排名；
3. 复制 `examples/消费ETF挑选报告-20260919.html`，替换：标题/`.sub`/KPI 数/决策矩阵卡片/7 张表/5 张图的数据数组/来源表/页脚；
4. 自查：所有数字与 `result.json` 及原始来源一致？待补字段是否标注？免责声明是否在位？
5. 交付：对话内用 `create_document`（记得去掉 ECharts CDN），或落盘后 `show_artifact`。
